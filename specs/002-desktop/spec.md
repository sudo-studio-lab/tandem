## 使用者情境與測試

### 情境 1：下載就能開始一個專案（優先度 P1）

小婕從一個網址下載 Tandem，點兩下安裝，按「用 GitHub 登入」，在瀏覽器確認。回到 app 後，她選一個現有的 GitHub repo，或按「開新專案」輸入名稱。app 自動把專案下載到電腦、做好 Tandem 的設定，然後打開看板。

**為什麼是 P1**：這是 001 最大的阻礙。
**獨立測試**：在一台沒裝 Node、gh 的電腦上，從下載網址開始，不開終端機，量看到看板要多久。

**驗收情境**：
1. **假設** 電腦上沒有 Node、npm、gh，**當** 使用者下載並安裝 app，**則** 不需要系統管理員權限，也不需要另外安裝任何東西。
2. **假設** 使用者按「用 GitHub 登入」，**當** 在瀏覽器確認，**則** app 記住登入，下次打開不用再登入。
3. **假設** 使用者選了一個現有的 repo，**當** 按「開始」，**則** app 自動下載到預設資料夾（可以改）、加上 Tandem 的設定並推上去，然後顯示看板。
4. **假設** 使用者按「開新專案」，**當** 輸入名稱，**則** app 在使用者的 GitHub 帳號（或使用者有權限的組織）建立一個私人 repo，並做完同樣的設定。
5. **假設** 選的資料夾已經是一個 git repo，**則** app 直接使用它，不重新下載。

### 情境 2：邀請隊友，隊友不用照任何步驟（優先度 P1）

小婕在 app 輸入 Roy 的 GitHub 帳號，按「邀請」。app 給她一段可以複製的文字，裡面只有一個下載網址。Roy 下載 app、用 GitHub 登入後，app 直接顯示「@jielle2453 邀請你加入 tandem」，他按「加入」就看到同一個看板。

**為什麼是 P1**：「邀請就能開始協作」是唯一一條不能違反的原則。
**獨立測試**：用兩個 GitHub 帳號、兩台電腦，被邀請的人只拿到那段文字，不另外說明，看他能不能自己加入。

**驗收情境**：
1. **假設** 小婕按了邀請，**則** 系統送出 GitHub 邀請，並產生一段分享文字：一句話說明加上下載網址。
2. **假設** Roy 已經裝好 app，**當** 他點分享文字裡的連結，**則** app 直接打開並顯示這個邀請。
3. **假設** Roy 登入 app 時有還沒接受的邀請，**則** app 主動列出來，按「加入」就接受邀請、下載專案、打開看板。不用去收信，也不用打指令。
4. **假設** 小婕的 repo 屬於組織，而組織禁止邀請外部協作者，**則** app 用白話說明原因和可以怎麼辦。

### 情境 3：一打開就看到大家在做什麼（優先度 P1）

Roy 打開 app，不用等誰寫狀態，就看到小婕昨天推了哪些 commit、開了哪個 PR、在哪些討論留了言，以及她的 agent 最後寫的狀態。

**為什麼是 P1**：這是「看得出效果」的關鍵。001 的看板要靠人或 agent 寫，所以剛開始是空的。
**獨立測試**：一個從來沒寫過狀態的成員推了幾個 commit、開了一個 PR，另一個人打開 app 時，能說出他最近在做什麼。

**驗收情境**：
1. **假設** 成員最近有推 commit（任何分支）、開或合併 PR、在討論留言，**則** 看板在這個成員底下列出最近的動態，並附上連結。
2. **假設** 成員的 agent 寫了狀態，**則** 狀態顯示在最上面，動態列在下面。
3. **假設** 成員超過 7 天沒有任何動態，**則** 顯示「最近沒有動態」，不留一片空白。
4. **假設** 這是剛開始的專案，紀錄還很少，**則** 看板仍然顯示 repo 的動態，不會整頁都是「還沒有…」。

### 情境 4：有人在等我時，我會知道（優先度 P1）

小婕的 agent 開了一個問題給 Roy。幾分鐘內，Roy 的電腦跳出通知「@jielle2453 在等你回答：誰決定分歧」。他點通知，就打開那則討論。

**為什麼是 P1**：「常常等來等去」是我們做這套系統的原因（notes/friction/F-20261115-9b3）。
**獨立測試**：開一個問 Roy 的問題，量 Roy 收到通知要多久，點通知是否直接打開那則討論。

**驗收情境**：
1. **假設** 有新的討論在等我、有 PR 請我審查、有任務指派給我，**則** app 在 5 分鐘內跳出系統通知，點了就打開那一項。
2. **假設** app 視窗關著，**則** app 仍在背景（工作列或選單列）運作並發出通知。
3. **假設** 同一件事已經通知過，**則** 不重複通知。
4. **假設** 使用者在設定裡關掉某一類通知，**則** 那一類不再通知。

### 情境 5：一鍵用自己的 agent 開始工作（優先度 P2）

Roy 在看板上按「用 Claude Code 開始」（或 Codex）。他的 agent 在這個專案的資料夾打開，第一句就告訴他上次之後跟他有關的變動。

**為什麼是 P2**：讓「看到」和「開始做」之間沒有步驟。但 agent 本身是每個人自己裝的，app 只負責打開它。
**獨立測試**：在裝了 Claude Code 或 Codex 的電腦上按按鈕，檢查 agent 是否在正確的資料夾打開，並報告變動。

**驗收情境**：
1. **假設** 電腦上裝了 Claude Code 或 Codex，**當** 使用者按對應的按鈕，**則** agent 在專案資料夾打開。
2. **假設** 兩個都沒裝，**則** 按鈕改成說明怎麼安裝，不會壞掉。
3. **假設** agent 的 hook 呼叫 `tandem`，**則** 不需要使用者另外安裝命令列工具，app 已經提供。

### 情境 6：在背景同步，不用管（優先度 P2）

app 開著時（包括縮到背景），紀錄自動同步。使用者從頭到尾不需要知道 git。

**驗收情境**：
1. **假設** `tandem/` 有變動，**則** app 在一分鐘內自動同步出去。
2. **假設** 使用者在功能分支上工作，分支上有還沒推送的程式碼 commit 和未提交的修改，**則** 紀錄照樣直接同步到 main，使用者的分支、commit 和修改完全不被碰到。
3. **假設** 同步遇到衝突，**則** app 停止自動同步，用白話說明並提供「幫我處理」或「打開資料夾」，絕不強制推送。
4. **假設** 使用者選了「開機時啟動」，**則** 開機後 app 自動在背景執行。

### 情境 7：自動更新（優先度 P2）

有新版本時，app 在背景下載，下次打開時自動換成新版，不用重新下載安裝檔。

### 情境 8：好幾個專案（優先度 P3）

一個人可以同時參加好幾個專案，在 app 裡切換。通知會標出是哪個專案。

## 需求

### 功能需求

- **FR-001**：提供 Windows 的安裝檔（我們兩個都用 Windows；macOS 之後再做，程式不寫死 Windows 專用的做法）。安裝不需要系統管理員權限，也不需要先安裝 Node、npm、gh；git 也不需要另外安裝（做法見 research）。
- **FR-002**：使用者用 GitHub 帳號登入 app，登入資訊存在作業系統的安全儲存區，不寫進任何檔案或 repo。
- **FR-003**：使用者可以從自己有權限的 GitHub repo 中選一個開始，或建立一個新的私人 repo。
- **FR-004**：開始一個專案時，app 自動下載 repo、執行 001 的設定（`tandem init` 的內容），並推送設定。
- **FR-005**：使用者在 app 裡輸入 GitHub 帳號就能邀請隊友，並得到一段可複製的分享文字。
- **FR-006**：使用者登入時，app 列出還沒接受的 repo 邀請；按「加入」就接受、下載、打開看板。
- **FR-007**：分享文字裡的連結在已安裝 app 的電腦上會打開 app，沒安裝時會引導下載。
- **FR-008**：看板為每個成員自動列出最近動態（commit、PR、討論留言），不需要任何人手動寫。
- **FR-009**：有新的事在等使用者（討論、PR 審查、指派的任務）時，發出系統通知，同一件事不重複通知；每一類都可以關掉。
- **FR-010**：app 關掉視窗後繼續在背景執行（工作列或選單列圖示），可以選擇開機時啟動。
- **FR-011**：紀錄一律直接同步到 repo 的預設分支（通常是 main），不管使用者目前在哪個分支。同步只碰 `tandem/`，絕不推送、改寫或暫存使用者的程式碼 commit 和未提交的修改（修正 001 的兩個問題：會順便推送程式碼 commit；在功能分支上記的決定要等合併才看得到）。
- **FR-012**：使用者可以從看板一鍵用 Claude Code 或 Codex 在專案資料夾開始工作。
- **FR-013**：app 提供 `tandem` 指令給 agent 的 hook 使用，使用者不需要另外安裝。
- **FR-014**：app 自動更新。
- **FR-015**：001 的命令列工具和瀏覽器看板繼續可以用，桌面版和它們讀寫同一份資料。
- **FR-016**：所有錯誤訊息用白話說明發生什麼事、使用者可以怎麼做，不顯示 git 或 API 的原始錯誤（可以展開看細節）。
- **FR-017**：系統不經手任何 AI 服務的登入或憑證（同 001 FR-017）。

### 主要資料

沿用 001 的資料（決定、討論、任務、狀態、成品），新增：

- **動態**：從 GitHub 和 git 推算出來的成員活動（commit、PR、討論留言），讀取時計算，不另外儲存到 repo。
- **通知紀錄**：本機記住哪些事已經通知過，存在本機，不進 repo。
- **專案清單**：這台電腦上加入過的專案和資料夾位置，存在本機。

## 成功標準

- **SC-001**：一個從沒用過終端機的人，從拿到分享文字到看到同一個看板，不超過 5 分鐘，過程中沒有打開終端機。
- **SC-002**：@theroyatlas 只拿到分享文字，不需要 @jielle2453 另外說明，就自己加入專案。
- **SC-003**：有人開問題給你之後，5 分鐘內收到通知。
- **SC-004**：專案剛開始、還沒有任何決定或狀態時，打開看板仍然看得到每個人最近在做什麼。
- **SC-005**：兩週內兩個人都**主動**打開 app 來看，不需要對方提醒（001 沒過這一關）。

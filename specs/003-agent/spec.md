# 功能規格：在 Tandem 裡直接用自己的 AI（003-agent）

**狀態**：草稿
**建立**：2026-11-15
**格式**：同 001、002（使用者情境 → 需求 → 成功標準）。這份只寫「做什麼、為什麼」，技術在 `plan.md`、`research.md`。
**依據的決定**：D-20261115-lwh7（先補 agent，訂閱或 API key 都能用）、D-20261115-r6x9（輕鬆，不能違反）、D-20261115-k5dj（核心只做共享決定和脈絡）、D-20261115-lt4n（照搬驗證過的做法）

## 這份要解決的問題

002 做完後，「用 Claude Code 開始」只是打開一個終端機。@jielle2453 說：

> 「我想要的是可以在裡面用自己的ai 而不是這樣跳出終端機ㄟ 應該是要可以讓使用者自己登入自己的訂閱 像t3code那樣 可以登好多個 然後就一樣一個對話框 可以選要用你有登入的那幾家的哪一個」

> 「我要t3code那樣可以登入也可以用API」

另外，原本的設計（「產品設計與功能總覽」）裡有三樣東西 001、002 沒做，而在 app 裡用 AI 需要它們：

1. **MCP 伺服器**：讓 agent 用工具讀寫團隊的決定和狀態，而不是靠它自己打 `tandem` 指令。
2. **引擎轉接**：由 Tandem 啟動 agent、送訊息、收結果、中斷。
3. **相容性測試**：同一組情境在 Claude Code 和 Codex 都要通過，確保兩家平等。

003 要做到：**在 Tandem 的視窗裡，用一個對話框跟自己的 Claude 或 Codex 工作。用訂閱或 API key 都行，可以同時登入好幾家，每次對話選要用哪一家的哪個模型。agent 自動知道團隊的最新狀況，也能直接記決定、更新狀態。**

## 使用者情境與測試

### 情境 1：在 app 裡跟自己的 AI 對話（優先度 P1）

小婕打開 Tandem，選好專案，按「新對話」。上方選「Claude · Opus」，輸入「幫我把登入頁的錯誤訊息改成白話」。回覆一個字一個字出現；agent 要改檔案時，對話裡跳出一張卡片，寫著要改哪個檔案，她按「同意」。做到一半她發現方向不對，按「停止」，再補一句話，agent 照新方向繼續。

**為什麼是 P1**：這就是使用者要的功能。
**獨立測試**：不開任何終端機，從新對話到 agent 改完一個檔案。

**驗收情境**：
1. **假設** 使用者已經登入至少一家，**當** 按「新對話」，**則** 可以選這幾家當中的任何一個模型，沒登入的不出現在選單裡（但有「登入其他家」的入口）。
2. **假設** agent 正在回覆，**則** 文字即時出現，工具呼叫（讀檔、執行指令、改檔案）以卡片顯示，可以展開看細節。
3. **假設** agent 要執行指令或改檔案，而使用者的設定要求先問，**則** 對話裡顯示要做什麼，使用者按「同意」「這次對話都同意」或「拒絕」。
4. **假設** agent 正在工作，**當** 使用者按「停止」，**則** agent 在幾秒內停下，已經做的修改留著，使用者可以接著說話。
5. **假設** 使用者關掉 app 再打開，**則** 之前的對話都還在，點進去可以接著聊。
6. **假設** 同一個專案同時開了兩段對話，**則** 兩段各自獨立，不互相干擾。

### 情境 2：登入自己的訂閱或 API key，可以登好幾家（優先度 P1）

Roy 第一次打開對話框，看到「還沒有可用的 AI」。他按「登入 Codex」，瀏覽器打開 OpenAI 的登入頁，用 ChatGPT 帳號登入後回到 Tandem，Codex 就可以用了。他又按「登入 Claude」，Tandem 打開 Claude Code 自己的登入流程，他選「用 API key」完成。現在選單裡兩家都有。

**為什麼是 P1**：沒有這個，情境 1 不能開始。
**獨立測試**：在一台已裝 Claude Code 和 Codex、但都沒登入的電腦上，完全在 Tandem 裡完成兩家的登入。

**驗收情境**：
1. **假設** 某一家還沒安裝，**則** 顯示白話說明和安裝連結，不顯示登入按鈕。
2. **假設** 某一家已安裝但沒登入，**當** 使用者按「登入」，**則** 走那一家**自己的**登入流程（瀏覽器或它自己的視窗）。Tandem 不顯示自己的帳號密碼欄位，也碰不到憑證。
3. **假設** 使用者想用 API key，**則** 同樣走那一家自己的流程（Codex 的 API key 登入、Claude Code 的 Console 登入），key 由那一家自己保存。
4. **假設** 使用者在終端機裡已經登入過 Claude Code 或 Codex，**則** Tandem 直接偵測到，不用再登入一次。
5. **假設** 使用者想看自己用的是哪種登入，**則** 設定頁顯示每一家「已用訂閱登入／已用 API key／未登入」，以及登出的入口。

### 情境 3：agent 自動知道團隊的事，也能直接記錄（優先度 P1）

小婕在對話裡說「好，那登入就用 GitHub，不要做 email 了」。agent 回一張卡片：「我記成這樣，對嗎？」，裡面是她的原話、決定內容、強度。她按「對」，決定就記進 Tandem，Roy 的看板馬上看得到。對話剛開始時，agent 就已經知道 Roy 昨天決定了什麼、誰在等她。

**為什麼是 P1**：這是 Tandem 和一般 AI 聊天視窗不一樣的地方（D-20261115-k5dj）。
**獨立測試**：在對話裡說出一個決定，確認看板上出現，而且原話一字不差。

**驗收情境**：
1. **假設** 開始一段新對話，**則** agent 一開始就拿到「上次之後跟你有關的變動」（跟 001 的開工報告相同內容）。
2. **假設** 使用者說出會影響別人的決定，**則** agent 先產生試寫的紀錄並在對話裡顯示，使用者確認後才正式寫入。原話逐字。
3. **假設** 對話告一段落，**則** agent 更新使用者自己的狀態（同 001 的規則），不改別人的。
4. **假設** agent 需要別人回答才能繼續，**則** 用開問題的工具，看板上顯示「在等誰」。

### 情境 4：在終端機用 agent 時也一樣（優先度 P2）

小婕有時還是習慣在終端機開 Claude Code 或 Codex。Tandem 的工具在那裡也能用，行為跟在 app 裡一樣。

**驗收情境**：
1. **假設** 專案用 Tandem 設定過，**當** 使用者在終端機打開 Claude Code 或 Codex，**則** agent 也能用 Tandem 的 MCP 工具，不需要另外設定。
2. **假設** 某一家沒辦法接 MCP（例如專案還沒被 Codex 信任），**則** 照舊用 `tandem` 指令和 hook，功能不少。

### 情境 5：兩家 agent 行為一致（優先度 P2）

每次改 Tandem 給 agent 的規則或工具，就跑一次相容性測試，Claude Code 和 Codex 都要通過。

**驗收情境**：
1. **假設** 執行相容性測試，**則** 同一組情境（見 plan）在兩家各跑一次，報告哪幾條通過、哪幾條沒過、各花多少額度。
2. **假設** 某一家沒有安裝或沒有登入，**則** 測試跳過那一家並清楚標示，不算通過。

### 情境 6：用 Claude Code 或 Codex 的人，不用 Tandem 的對話框也沒關係（優先度 P3）

對話框是多一個選擇，不是唯一入口。終端機、VS Code 外掛、其他 app 照常能用，Tandem 的紀錄一樣會更新。

## 需求

### 功能需求

- **FR-001**：Tandem 提供 MCP 伺服器（`tandem mcp`），工具涵蓋現有的命令列功能：開工報告、記決定（含試寫）、更新狀態、開問題、開分歧、開任務、查決定、檢查格式。
- **FR-002**：設定專案時，Tandem 把自己的 MCP 伺服器登記給 Claude Code 和 Codex（只寫專案資料夾裡的設定，不改使用者電腦上的全域設定）。
- **FR-003**：Tandem 能在背景啟動使用者**自己安裝、沒有修改過**的 Claude Code 和 Codex，送訊息、即時接收回覆和工具呼叫、回應核准請求、中斷、接續之前的對話。
- **FR-004**：對話框可以選 agent 和模型，只列出已安裝而且已登入的；每段對話記住它用的 agent 和模型。
- **FR-005**：登入一律走各家自己的流程。Tandem 不提供自己的 Claude 或 ChatGPT 登入頁面，不收集、不儲存、不轉送任何 AI 服務的帳號憑證或 API key（維持 001、002 的 FR-017）。
- **FR-006**：Tandem 能顯示每一家的狀態：未安裝、未登入、已用訂閱登入、已用 API key 登入；並提供登入和登出的入口。
- **FR-007**：agent 要執行指令、改檔案或做其他需要核准的動作時，在對話裡請使用者決定。預設的核准規則和各家自己的預設一致，使用者可以調整。
- **FR-008**：對話紀錄存在使用者自己的電腦，不進 repo、不上傳（原始對話屬於個人）。只有使用者確認過的決定、狀態、問題才會寫進團隊紀錄。
- **FR-009**：每段對話開始時，agent 拿到跟 001 開工報告相同的團隊資訊。
- **FR-010**：提供相容性測試，同一組情境在 Claude Code 和 Codex 各跑一次並產生報告。
- **FR-011**：介面上不把 Claude Code、Codex 或 Anthropic、OpenAI 的名字當成 Tandem 自己功能的名字；選單顯示「Claude」「Codex」，說明文字可以寫「使用你的 Claude Code」。
- **FR-012**：錯誤訊息用白話說明（例如「Claude 的額度用完了，大約 3 小時後恢復」），可以展開看原始訊息。

### 主要資料

沿用 001、002 的資料，新增（全部只存在本機）：

- **對話**：專案、使用的 agent 和模型、該 agent 自己的對話編號（用來接續）、建立和最後使用時間、標題。
- **對話內容**：使用者訊息、agent 回覆、工具呼叫和結果、核准紀錄，依時間排列。
- **agent 狀態**：每一家是否安裝、版本、登入方式（不存憑證本身）。

## 成功標準

- **SC-001**：在一台已安裝 Claude Code 和 Codex 的電腦上，不開終端機，從打開 Tandem 到跟兩家各完成一次對話，5 分鐘內完成。
- **SC-002**：在對話裡說出的決定，100% 經過使用者確認才寫入，原話逐字。
- **SC-003**：相容性測試的情境，兩家都通過至少 90%；沒通過的列成已知差異。
- **SC-004**：按「停止」後 5 秒內 agent 停下。
- **SC-005**：檢查 Tandem 的程式碼、設定和本機檔案，找不到任何 AI 服務的憑證或 API key。

## 前提假設

- 使用者自己安裝 Claude Code 和 Codex。Tandem 不內建、不代為安裝（Anthropic 規定產品裡執行的必須是原版程式；而且使用者本來就會裝）。
- 只做 Windows，跟 002 一樣。
- sudo-studio-lab 會同意 Anthropic 的商業條款（產品裡執行 Claude Code 的條件之一），這是人工步驟。
- 一段對話只用一個 agent。換 agent 等於開新對話（之後可以加「把這段對話交給另一個 agent」）。

## 不在這份範圍

- 房間（多人一起跟 agent 對話）：004-room。這份的對話只有使用者自己。
- 把對話交給另一家 agent（原本設計的「驗證過的交接」）。
- 雲端執行、背景工人（使用者不在時繼續做）：團隊大腦那份。
- Claude、Codex 以外的 agent（OpenCode、Gemini、Cursor）：轉接層要留好擴充空間，但這份不做。
- 用 Agent SDK 搭配訂閱登入：Anthropic 不允許，見 research A1。

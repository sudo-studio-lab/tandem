# 002 桌面版（Windows）

> 這是紀錄，不是定案。描述 002 做了什麼、怎麼做、為什麼，以 0.2.1 版的程式為準。
> 舊的規格、計畫、研究文件跟程式不一致的地方，以程式為準，差異寫在「跟原本計畫不一樣的地方」。

## 要解決的問題

001 做出來之後，Jielle 和 Roy 都不太想用，原因有兩個：

1. **開始很麻煩**：要先裝 Node、clone、`npm install`、`npm run build`、`npm link`，每次要看看板還得開終端機。
2. **看不到效果**：看板的內容要靠 agent 寫狀態和決定才會有，剛開始幾乎是空的，感覺不到它幫了什麼。

002 的目標：下載、點兩下、用 GitHub 登入，就能開始或加入一個專案，不用碰終端機；一打開就看得到每個人最近在做什麼，就算沒人手動寫也一樣；有人在等你時，你會知道。

## 做了什麼

**下載就能開始一個專案。** 從下載頁拿到安裝檔，點兩下安裝（不需要系統管理員權限，也不用另外裝 Node、npm、gh 或 git）。按「用 GitHub 登入」，app 給一組代碼，到瀏覽器貼上確認，回來就登入了，下次打開不用再登入。接著可以：選一個自己有寫入權限的 repo、按「開新專案」在自己的帳號或組織下建一個私人 repo，或指定電腦裡已經有的資料夾。app 會自動下載專案、做好 Tandem 的設定，然後打開看板。

**邀請隊友，隊友不用照任何步驟。** 在 app 裡輸入隊友的 GitHub 帳號按邀請，app 送出 GitHub 的協作者邀請，並給一段可以複製的分享文字（一句說明加一個下載頁網址）。隊友裝好 app、用 GitHub 登入後，app 會主動列出「@某某 邀請你加入 owner/repo」，按「加入」就接受邀請、下載專案、打開看板，不用去收信也不用打指令。邀請失敗時（例如組織禁止外部協作者、帳號打錯、超過每天邀請上限）用白話說明。

**一打開就看到大家在做什麼。** 看板上每個人一張卡片，最上面是 agent 寫的狀態，下面是從 GitHub 自動整理的最近 7 天動態：推了哪些 commit（任何分支）、開了或合併了哪些 PR、在討論或 issue 留了言，每一項都有連結。沒寫過狀態的人也有動態可看；7 天內完全沒動靜就寫「最近 7 天沒有動態」，不留一片空白。

**有人在等我時，我會知道。** 有討論在等你回答、有 PR 請你審查、有任務指派給你時，Windows 會跳出通知，點了就打開那一項。同一件事不重複通知；三類通知（等你回答、請你審查、指派任務）都可以在設定裡個別關掉。看板最上方有一條「有 N 件事在等你」，工作列圖示上也會出現紅點。

**關掉視窗還在背景執行。** 關視窗只是縮到右下角的工作列圖示，繼續同步和通知。第一次關的時候會跳一則通知說明它還在哪裡。設定裡可以勾「開機時自動啟動」，開機後會直接在背景待命，不開視窗。

**紀錄自動同步，不用管 git。** agent 記下決定或狀態時，紀錄直接寫到 GitHub 上 repo 的預設分支（通常是 main），不管使用者現在在哪個分支、有沒有沒推送的 commit 或沒存的修改，全都不碰。離線時先存在本機，連上網再送。

**從看板打開自己的 agent。** 「更多動作」選單裡可以「在終端機打開 Claude Code」或 Codex，agent 會在專案資料夾打開。沒裝的話會說明怎麼裝，不會替使用者安裝。

**agent 的 hook 不用另外裝 `tandem`。** app 每次啟動會把 `tandem` 指令放到使用者的 PATH 上，Claude Code 和 Codex 的 hook 直接就能用。

**自動更新。** app 在背景檢查並下載新版，下次打開時自動換成新版。

**好幾個專案。** 一個人可以加入好幾個專案，在上方切換；其他專案有事在等你時，切換按鈕上會有數字。

001 的命令列工具和瀏覽器看板繼續可以用，和桌面版讀寫同一份資料。

## 不在這次範圍

- 房間（多人一起跟一個 agent 討論）、派工給別人的 agent、在 app 裡直接跟 agent 對話：屬於後續功能。0.2.1 的介面已經有「跟 AI 對話」和「房間」分頁，但那是之後的工作，不算在 002。
- 雲端網頁版（不用安裝就能看）。
- macOS 版（程式簽章和公證要另外處理）。程式盡量不寫死 Windows 專用的做法。
- 手機版。
- 程式簽章：先不做，見下面。
- 安裝或登入 Claude Code、Codex：每個人自己裝，app 只負責打開它，也不經手任何 AI 服務的帳號或憑證。

## 怎麼做的

### 整體架構

桌面版不是另寫一套。Electron（用網頁技術做桌面程式的框架）的主程式只負責「殼」：視窗、工作列圖示、通知、開機啟動、自動更新、`tandem://` 連結、PATH 上的指令。真正做事的是 001 就有的本機伺服器（`apps/cli` 的 `server.ts`），桌面版用 Electron 自己的執行檔以 Node 模式（`ELECTRON_RUN_AS_NODE=1`）把它當子程式啟動，視窗再打開這個伺服器提供的看板網頁（`apps/web`）。

- 啟動時，主程式產生一組一次性通行碼，經 stdin 交給伺服器（不放在命令列，別的程式看不到）。伺服器挑一個空的連接埠，在 stdout 印一行 JSON 說「我好了，在哪個埠」，視窗才載入網頁。網頁第一次載入時用通行碼換成 cookie。
- 伺服器只聽 127.0.0.1，並檢查 Host 標頭，擋掉從別的網域繞進來的請求。
- 伺服器掛掉會自動重啟，等待時間從 0.5 秒開始加倍，最多 10 秒。日誌寫在 app 的 logs 資料夾。
- 用單一實例鎖，同時只會有一個 Tandem 在跑；第二次打開（或點了 `tandem://` 連結）會把已經開著的視窗叫到前面。
- 視窗只信任自己伺服器的網頁：外部連結一律用系統瀏覽器開，而且只接受 https。

在 repo 裡打 `tandem` 也會啟動同一個多專案伺服器（預設埠 4318），用瀏覽器看，並先把目前這個 repo 加進專案清單。瀏覽器版不跳系統通知，只在看板和分頁標題上顯示等你的數量。

### 多專案伺服器

一個伺服器管這台電腦上的所有專案，每個專案在記憶體裡有自己的狀態（看板資料、動態、同步狀態、等你的數量）。API 分成幾組：

- **登入**：`/api/session`（目前登入的人、專案清單、目前專案、版本）、裝置碼登入的開始與查詢、登出。
- **GitHub 選項**：我能寫入的 repo、可以建 repo 的帳號和組織、待接受的邀請和接受邀請。
- **專案**：從現有 repo 開始、開新 repo、加入本機資料夾、從清單移除（不刪檔案）、切換目前專案。開始、開新、接受邀請這類要跑一陣子的動作會先回傳一個操作編號，進度再用事件推給網頁。
- **單一專案**：看板資料、重新抓 GitHub、立即同步、邀請、打開 agent、打開資料夾。
- **設定**：通知開關、開機啟動。
- **事件**：`/api/events` 用 SSE（伺服器持續往網頁推訊息的連線）送出看板更新、同步狀態、進度、通知和 session 變動。
- 0.2.1 另外有對話和房間的 API，屬於後續功能。

本機的 app 資料（專案清單、通知設定、已經通知過的項目、預設專案資料夾）存在 `%APPDATA%\Tandem\app.json`，不進 repo。專案預設下載到使用者資料夾下的 `Tandem\<repo 名>`，名字被占用就加上 `-2`、`-3`。

### 資料流程的改變：紀錄直接寫到遠端預設分支

這是 002 對 001 最大的改動。001 的同步會在使用者目前的分支上 commit `tandem/`，再 `pull --rebase --autostash` 和 `push`，造成：分支上還沒推的程式碼 commit 會被順便推上去（在 main 上等於繞過 PR）；在功能分支上記的決定，隊友要等合併才看得到；背景程式還會改寫使用者的 commit、暫存使用者的修改。

002 把紀錄的讀寫抽成一個「資料存放處」（`packages/core/src/data/`），寫入時完全不經過使用者的工作目錄：

1. 要寫的內容先放進本機待送佇列（`.git/tandem/outbox/`，一筆一個檔，先寫暫存檔再改名，避免讀到寫一半的檔）。
2. 拿到檔案鎖（`.git/tandem/lock`），只抓遠端預設分支的最新版本。
3. 用一個暫時的 index（git 用來組下一個 commit 的暫存區，這裡另外開一個，不動使用者的），以遠端最新版為底，把要寫的檔案放進去，直接組出新的 commit，作者是使用者自己。
4. 把這個 commit 推到遠端預設分支。被拒絕（別人剛好先推）就從第 2 步重做，最多 3 次；還是不行就留在佇列，之後再試。
5. 離線就留在佇列，下次同步時再送。

讀取時，看板和 brief 讀的是「遠端預設分支上的 `tandem/`」再疊上佇列裡還沒送出的內容；工作目錄裡的 `tandem/` 只是使用者分支上的副本，不當資料來源。

衝突：紀錄是一筆一檔、狀態是一人一檔，所以重做通常不會衝突。唯一的例外是「新建的檔案在遠端已經有同名但內容不同的檔」，這筆會被移到 `.git/tandem/conflicts/`，同步狀態顯示為需要處理，不會強制推送。預設分支設了保護規則時會推不上去，顯示錯誤說明。

另外：開始一個專案時，Claude Code 和 Codex 的設定檔是寫在工作目錄、commit 在使用者目前的分支上推出去的（這樣隊友的 agent 拿到 repo 就有同樣的設定）。只 commit 這幾個設定檔；如果分支上還有使用者自己沒推的 commit，就不推，等使用者自己推分支時一起上去。

### 登入

用 GitHub 的 OAuth App 加「裝置碼流程」（app 顯示一組代碼，使用者到 GitHub 網頁輸入確認；不用在 app 裡打密碼，也不用本機回呼網址）。OAuth App 註冊在 sudo-studio-lab 組織下，Client ID 寫在程式裡（它是公開的，不是秘密），可以用環境變數換掉。權限範圍是 `repo` 和 `read:org`。

權杖存在 Windows 認證管理員（透過 `@napi-rs/keyring`），不寫進任何檔案或 repo。找權杖的順序：環境變數（`TANDEM_TOKEN`、`GH_TOKEN`、`GITHUB_TOKEN`）→ 認證管理員 → `gh auth token`。

git 推送時，權杖只放在 git 子程式的環境變數裡（用 `GIT_CONFIG_COUNT` 臨時加一個認證標頭，並清掉 credential helper），不寫進 `.git/config`，也不出現在命令列。

### 邀請

- 邀請：呼叫 GitHub 的協作者邀請 API，回傳分享文字。分享文字裡的網址是公開下載頁，repo 名稱放在網址 `#` 後面（瀏覽器不會把 `#` 後面送到伺服器）。
- 加入：登入後呼叫 GitHub「我收到的 repo 邀請」API 列出邀請；從分享連結進來時，連結裡的 repo 會排到最上面。按加入就接受邀請、clone、設定、打開看板。
- `tandem://join?repo=owner/name` 連結：已安裝 app 時會打開 app 並帶到那個邀請。程式會檢查格式，其他內容一律忽略。

### 同步和 GitHub 輪詢

- 寫入：agent 記紀錄當下就走上面的流程直接推出去。
- 背景：伺服器每 3 分鐘對每個專案做一次「送出佇列 + 抓遠端預設分支」，再重新抓 GitHub（討論、PR、任務、成員動態），重算看板和通知。看板上也有立即同步和重新整理的按鈕。
- 成員動態：用 GitHub GraphQL 一次抓最近更新的分支上的 commit、最近的 PR、討論的留言，再用 REST 抓 issue 留言，在記憶體裡整理成每人最近 7 天、最多 10 筆。同一天同一分支的 commit 合成一筆。成員名單是 repo 協作者加上這段時間有動態的人，機器人帳號排除。動態不存進 repo。

### 通知

伺服器每次重算看板，就算出「現在在等我的事」，扣掉已經通知過的和被關掉的類別，用 SSE 送出通知事件。Electron 主程式訂閱這個事件流，跳 Windows 通知；點通知會打開視窗並用瀏覽器開那一項。已通知過的項目記在 `app.json`。伺服器啟動後第一次算的時候，現有的項目只標成已看過、不跳通知，避免一開 app 就跳一大串。

等我的數量同時顯示在：看板最上方的提示條、工作列圖示的紅點、工作列圖示的滑鼠提示文字、視窗標題。

### 工作列圖示和開機啟動

- 關視窗只是隱藏，工作列右下角的圖示選單有「開啟 Tandem」「暫停同步」「結束」。
- 開機啟動用 Electron 的登入項目設定，帶 `--hidden` 參數，開機後只在背景跑。預設關閉，在設定裡勾選。
- 視窗大小和位置會記住，螢幕配置變了就回到預設位置。

### `tandem` 指令（給 agent hook 用）

app 每次啟動都在 `%LOCALAPPDATA%\Tandem\bin\` 重寫兩個檔：`tandem.cmd`（給 PowerShell、cmd）和沒有副檔名的 `tandem`（sh 腳本，給 Git Bash）。兩個都是用 app 的執行檔以 Node 模式跑 CLI，並指定用內建的 git。檔案開頭有標記，不是我們寫的同名檔就不碰。接著把這個資料夾加進使用者 PATH（寫在使用者自己的登錄區，保留原本的值型態，然後通知系統環境變數變了）；讀不到 PATH 就放棄，絕不覆寫。第一次加進 PATH 時會跳通知，提醒重開 Claude Code 或 Codex 才讀得到。

### 內建 git

用 dugite（GitHub Desktop 用的 git 包裝）帶一份 Git for Windows，打包在安裝資料夾的 `resources/git`。程式執行 git 時先看環境變數 `TANDEM_GIT`，有就用內建的並設好它需要的環境，沒有才用系統的 git。Claude Code 和 Codex 自己跑 git 時仍用系統的 git，跟 Tandem 無關。

### 自動更新

用 electron-updater，從公開 repo `sudo-studio-lab/tandem-releases` 的 Releases 拿新版。啟動時檢查一次，之後每 6 小時檢查一次，有新版就在背景下載並記住版本號；下一次啟動時，確認這個版本已下載好，就先停掉伺服器子程式（它會鎖住執行檔）再安裝重開。關 app 時不安裝。

### 打包和發布

- 打包：electron-builder 產生 NSIS 安裝檔（per-user、一鍵安裝、不需要管理員權限），只做 x64。主程式和 preload 用 esbuild 整包，不帶 node_modules；CLI（含看板網頁）、內建 git、認證管理員的原生模組放在 `resources/` 底下（不在 asar 封裝檔裡，因為它們要被當成真的檔案執行或載入）。安裝檔約 150 MB。appId 是 `com.sudo-studio-lab.tandem`，同時是 Windows 通知用的識別碼，發布後不能改。
- 發布：在本機執行 `npm run release -- <版本> "<這版改了什麼>"`，它檢查沒有未 commit 的修改，打一個附註 tag 推上去。GitHub Actions（`.github/workflows/release.yml`）收到 `v*` tag 後，在 Windows 機器上用 tag 的版本號打包，再用一個只能寫 `tandem-releases` 的權杖（secret `RELEASES_TOKEN`）把安裝檔、`latest.yml`、blockmap 傳到 `tandem-releases` 的 Release，tag 的訊息就是更新說明。已安裝的 app 下次啟動時就會拿到。沒有 GitHub Actions 時可以加 `--local` 改在自己電腦打包上傳。
- 下載頁放在 `tandem-releases` 的 GitHub Pages（`sudo-studio-lab.github.io/tandem-releases/`）。

## 技術選擇和原因

### 紀錄直接寫到預設分支，不經過使用者的 checkout

- **選了什麼**：用 git 底層指令（read-tree、hash-object、update-index、write-tree、commit-tree）在遠端預設分支上直接組 commit 推上去，加本機待送佇列和跨程式的檔案鎖。
- **為什麼**：紀錄要「直接進 main、隊友馬上看得到」，同時絕不能碰使用者的程式碼、commit 和未存的修改。這個做法不需要第二個工作目錄，使用者在 main 上時下次 pull 就會快轉拿到，在功能分支上合併 main 也不會衝突。
- **參考了誰**：Beads 早期用隱藏的 git worktree 同步到獨立分支，後來因為卡住的 worktree 會擋到使用者切換分支而放棄，改放在獨立的 ref；git-bug、git-appraise 用底層指令寫入、不經過工作目錄；GitHub 網頁編輯檔案也是直接在遠端產生 commit。
- **沒選的做法**：沿用 001 在使用者分支上 commit 再 rebase 推送（會帶出程式碼 commit、改寫歷史）；另開一個 worktree（Beads 踩過的坑）；寫到獨立的 ref（在 GitHub 網頁上看不到、點不到紀錄，違背 001 的設計）。

### 成員動態從 GitHub 推算，不存檔

- **選了什麼**：每次重整時從 GitHub 抓各分支的 commit、PR、討論和 issue 留言，在記憶體整理成每人最近 7 天的動態，不寫進 repo。
- **為什麼**：001 的看板要靠人或 agent 寫才有內容，剛開始是空的。commit 和 PR 本來就在發生，不需要任何人多做事就能讓看板有東西。
- **參考了誰**：GitHub repo 的 Insights、Linear 的活動紀錄，都是從既有事件推算。
- **沒選的做法**：把動態存成檔案進 repo（多一堆紀錄、還要同步）。原本也考慮用本機 `git log` 依 email 比對作者當備援，但實作時改成只用 GitHub 回傳的帳號：email 對不到帳號的 commit 直接略過，因為用 email 猜容易把動態算到錯的人頭上。

### 內建 git：dugite

- **選了什麼**：用 dugite 隨 app 帶一份 Git for Windows，靠 `TANDEM_GIT` 環境變數指定。
- **為什麼**：使用者不用另外裝 git。dugite 是 GitHub Desktop 在用、MIT 授權、持續維護的套件。代價是安裝檔變大（git 壓縮後約 47 MB）。
- **參考了誰**：GitHub Desktop。
- **沒選的做法**：要求使用者自己裝 git（多一個步驟，違背「下載就能用」）；用純 JavaScript 實作的 git（行為和真 git 不完全一樣，推送和認證要另外處理）。

### 沒有 npm 也能讓 `tandem` 在 PATH 上

- **選了什麼**：在 `%LOCALAPPDATA%\Tandem\bin` 放 `.cmd` 和 sh 兩種小腳本，用 app 自己的執行檔以 Node 模式跑 CLI，再把資料夾加進使用者 PATH。
- **為什麼**：Claude Code 在 Windows 預設用 Git Bash 跑 hook，沒有 Git Bash 時用 PowerShell，所以兩種殼都要能找到 `tandem`（npm 也因為同樣原因會同時產生 sh 和 `.cmd`）。改 PATH 時保留原本的值型態、讀不到就放棄，避免把使用者的 PATH 弄壞。
- **參考了誰**：T3 Code 的桌面版用同樣做法上線（`DesktopCliShim.ts`）；npm 的雙檔案做法。
- **沒選的做法**：要求使用者用 npm 全域安裝 CLI（需要 Node）；另附一個獨立的 console 啟動程式（原本列為備案，目前沒有用到）。
- 補充：app 自己啟動 agent 對話時，MCP 伺服器直接用 app 的執行檔啟動，不依賴 PATH，所以 PATH 還沒生效時也能用。

### GitHub 登入：OAuth App 加裝置碼流程

- **選了什麼**：註冊在 sudo-studio-lab 組織下的 OAuth App，開啟裝置碼流程，權限 `repo`、`read:org`；權杖存 Windows 認證管理員；權杖不設過期。
- **為什麼**：裝置碼流程不需要本機回呼網址，也不用在 app 裡處理密碼。組織自己的 OAuth App 不受組織的「第三方 OAuth 存取限制」影響；其他組織的使用者第一次用時，需要他們的組織擁有者核准一次。權杖不過期就不用處理每 8 小時換一次權杖。
- **參考了誰**：gh 用內嵌公開 Client ID 的裝置碼流程；GitHub Desktop 用自己的 OAuth App。
- **沒選的做法**：GitHub App。它的權杖只能用在已經安裝這個 App 的 repo，被邀請的人在接受邀請前不可能已經裝好，「邀請就能開始」會被打斷；而且接受邀請需要很大的管理權限。也不再像 001 那樣只靠借用 gh 的登入（使用者要先裝 gh），不過 gh 的權杖仍保留為最後的備援。

### 先不做程式簽章

- **選了什麼**：002 先發沒簽章的安裝檔。第一次安裝時 Windows SmartScreen 會顯示「Windows 已保護您的電腦」，要按「其他資訊 → 仍要執行」。
- **為什麼**：目前只有 Jielle 和 Roy 兩個人用，可以接受這一次的警告。簽章要花錢或要符合資格：SignPath Foundation 免費但要求開源；用公司名義買 OV 憑證要花錢；Azure Artifact Signing 的個人申請只限美國和加拿大，組織只限美國、加拿大、歐盟和英國，台灣不符合。
- **風險**：Windows 11 的 Smart App Control 開啟時，會直接擋下沒簽章的程式，沒有「仍要執行」可按。
- **沒選的做法**：現在就買憑證或申請簽章服務，等對外發布前再決定。

### 邀請：登入後自動列出，連結只是加分

- **選了什麼**：主流程不靠連結。被邀請的人登入後，app 主動列出待接受的邀請；分享文字放的是 https 下載頁，`tandem://` 連結只是已安裝時的捷徑。
- **為什麼**：聊天軟體多半不會把 `tandem://` 這種自訂連結變成可以點的，GitHub 的 Markdown 也會把它拿掉；https 網址到哪裡都點得開。
- **參考了誰**：Zoom、Discord 的邀請連結都是先打開 https 網頁，再叫起 app。
- **限制**：接受邀請前讀不到私人 repo 的內容，分不出它是不是 Tandem 專案，所以用連結裡的 repo 名稱把它排到最上面；使用者也可能已經從 email 接受了邀請，這時就直接當成已經有權限的 repo 來開始。

### 安裝檔和下載頁放在另一個公開 repo

- **選了什麼**：公開 repo `sudo-studio-lab/tandem-releases`：Releases 放安裝檔和 `latest.yml`，GitHub Pages 放下載頁。程式碼留在私人 repo，只用一個只能寫 `tandem-releases` 的權杖發布。
- **為什麼**：electron-updater 從私人 repo 更新時，每個使用者都要提供權杖；免費方案的 GitHub Pages 只支援公開 repo。安裝檔公開沒有關係，下載頁不放任何私人資料。
- **沒選的做法**：放在私人 repo 的 Releases（要登入才能下載，更新也要權杖）；另外架網站或用雲端儲存（多一套要維護的東西）。

### Electron 執行同一份伺服器

- **選了什麼**：主程式用自己的執行檔以 Node 模式啟動 CLI 的伺服器，通行碼經 stdin 傳、就緒時從 stdout 回報埠號，掛掉就重啟；單一實例鎖。
- **為什麼**：瀏覽器版和桌面版共用同一份伺服器和看板程式，不用寫兩套；不需要使用者裝 Node，因為 Electron 本身就能當 Node 用。
- **參考了誰**：T3 Code 的 `DesktopBackendManager.ts`。
- **跨程式的同時寫入**：常駐的伺服器和 agent hook 跑的 `tandem` 是不同的程式，001 的 git 排隊只在同一個程式裡有效。所以寫入時另外用檔案鎖把「抓遠端、組 commit、推送」串起來，鎖太久沒更新（60 秒）就當作殘留可以拿走；佇列檔用先寫暫存檔再改名的方式寫。
- **沒選的做法**：把伺服器邏輯搬進 Electron 主程式（瀏覽器版就得另寫一套）；要求使用者另外裝 Node 跑伺服器。

### 工作列、通知、開機啟動、自動更新、打開 agent

- **通知**：設定 AppUserModelId（Windows 用來辨認是哪個 app 發的通知），和安裝程式建的捷徑一致。因為 Windows 的「勿擾」會安靜丟掉通知，所以等你的數量也顯示在工作列和看板上，不只靠通知。參考 Electron 官方通知文件。
- **工作列圖示**：關視窗只隱藏，讓通知和同步繼續。
- **開機啟動**：用 Electron 的登入項目設定，預設關閉，由使用者自己選。
- **自動更新**：NSIS 安裝檔加 electron-updater。只有工作列圖示、沒有視窗的 app 偵測不到 Windows 關機，所以不能在關機時更新，改成「下次啟動時安裝」。
- **打開 agent**：有 Windows Terminal 就用 `wt.exe -d <資料夾> claude`（或 `codex`），沒有就用 PowerShell；先用 `where` 確認有沒有裝。用參數陣列啟動，不拼接命令字串，避免資料夾名稱被當成指令執行。沒選：`claude://`、`codex://` 這類網址連結（要看各家桌面版支援，行為不一致），原本列為選用，目前沒做。

## 跟原本計畫不一樣的地方

- **發布改由 GitHub Actions 做**：原本計畫在本機打包上傳。安裝檔約 150 MB，上傳很慢，所以改成推 tag 後由 GitHub 打包上傳到 `tandem-releases`；本機打包保留為 `--local` 備案。
- **介面重新設計**：原本的看板是一欄一欄的清單。0.2.1 改成：最上方「有 N 件事在等你」的提示條，中間是每個人的卡片（狀態加最近動態）和等待中的事，右側一欄放決定、討論和任務。上方有「看板 / 跟 AI 對話 / 房間」三個分頁，後兩個是 002 之後加的功能。打開 agent、打開資料夾、重新整理收進「更多動作」選單。
- **自動更新的做法**：原本打算用 electron-updater 的「下次啟動時安裝」設定，但使用的 6.8.11 版沒有這個選項，改成自己記住已下載的版本號、下次啟動時安裝；並加上每 6 小時檢查一次。
- **更新檔的簽章清單沒有做**：原本打算用簽章清單確保更新沒被竄改，目前設定檔裡沒有這一項，更新只靠 `latest.yml` 裡的檔案雜湊確認下載完整。程式簽章也延後。
- **同步時機**：原本希望 `tandem/` 有變動一分鐘內同步出去。現在是寫入當下就直接推，失敗的留在佇列，每 3 分鐘的背景重整時再送。core 裡有一個監看資料夾變動的排程器，但伺服器沒有用它。
- **GitHub 輪詢**：每 3 分鐘一次，比原本「5 分鐘內收到通知」的目標快。
- **通知沒有標出專案**：原本說通知要標出是哪個專案，目前通知的標題和內文只有誰、什麼事，沒有專案名稱。
- **成員動態**：沒有用本機 `git log` 依 email 比對的備援，只用 GitHub 回傳的帳號（見上）。
- **工作列數字**：原本說工作列圖示要顯示數字，實際是在工作列的程式圖示上加紅點、在滑鼠提示文字和視窗標題寫數量。
- **「暫停同步」**：工作列選單上有這一項，但目前按了沒有作用（伺服器還沒有對應的功能）。
- **開機啟動的詢問**：原本打算第一次登入後問一次，實際是放在設定裡讓使用者自己勾。
- **打包位置**：原本打算把 git 放在 asar 的解壓區，實際放在 `resources/` 底下；認證管理員的原生模組也另外複製一份給 CLI 用。
- **找權杖的順序**：多了 `GH_TOKEN`、`GITHUB_TOKEN` 兩個環境變數。
- **Discussions**：開新專案時會直接打開 Discussions（repo 是 app 剛建的）；從現有 repo 或本機資料夾開始時不會自動改 repo 設定，沒開的話改用 Issues。
- **設定檔會 commit 在目前分支**：原本強調「完全不碰使用者的分支」，但開始專案時 agent 設定檔還是要 commit 在目前分支上，才能讓隊友的 agent 拿到；只有這些檔，而且分支上有使用者自己沒推的 commit 時就不推。

## 已知的限制

- 只有 Windows x64。
- 安裝檔沒有簽章：第一次安裝會看到 SmartScreen 警告；開了 Smart App Control 的電腦會直接被擋，裝不起來。
- 安裝檔約 150 MB，主要是 Electron 和內建 git。
- 預設分支設了保護規則時，紀錄推不上去。
- 使用者在預設分支上手動改了 `tandem/` 的檔案，可能和背景寫入衝突，要人處理。
- commit 作者的 email 沒有連到 GitHub 帳號時，這些 commit 不會出現在動態裡。動態只看最近更新的 30 個分支、每分支 30 個 commit、30 個 PR、20 則討論（各取最後 10 則留言）和 50 則 issue 留言，很活躍的 repo 會漏掉一些。
- 其他組織的使用者第一次登入時，可能要他們的組織擁有者核准 Tandem 的 OAuth App。
- 已經開著的 Claude Code、Codex 看不到新加的 PATH，第一次安裝後要重開。
- Windows「勿擾」開著時通知會被安靜丟掉，只能靠工作列和看板上的數量。
- 「暫停同步」目前沒有作用。
- 原本列為要實機確認的幾件事，這份紀錄沒有確認結果：用 Node 模式跑的 `tandem` 當 hook 時 stdin/stdout 傳 JSON 是否在 Git Bash 和 PowerShell 都正常、Codex 在 Windows 用哪個殼跑 hook、沒簽章時自動更新能否從頭跑完、分享連結貼在 LINE 等聊天軟體裡的樣子。
- 下載頁放在 `tandem-releases` repo，不在這個 repo 裡，這份紀錄沒有檢查它的內容（例如是否會嘗試用 `tandem://` 叫起 app）。

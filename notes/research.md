# Tandem 的驗證問題

這份只記錄產品要驗證的問題。背景研究和整理前的文件保存在私人團隊資料庫。

| 問題 | 怎麼驗證 | 通過的訊號 |
|---|---|---|
| 共享決定是否減少傳話 | 一人記決定，另一人的 agent 開工或繼續對話 | 對方能讀到原話、原因與相關限制 |
| 任務板是否容易理解 | 兩人查看同一個專案 | 看得出負責人、進度和相關 PR |
| 共享脈絡是否維持一致 | 兩人先後與同時修改文件 | 新版本可讀，舊版本不能靜默覆蓋新內容 |
| Agent 訊息是否有幫助 | 兩人自行啟用後互問專案問題 | 對方能回答，主對話收到備註，且不能取得額外動作權限 |
| 對話分享是否符合預期 | 預覽選取內容，再由本人確認 | 只有這個專案、本人選定的內容會同步 |
| 交接是否足夠清楚 | 改指派並附交接筆記 | 接手者知道已完成、未完成與下一步 |
| 成員管理是否完整 | 邀請、加入、離開、移除與重設連結 | 權限與畫面一致，舊連結失效有清楚說明 |

## 證據界線

- 程式測試：驗證規則與錯誤處理。
- MOCK 畫面：驗證排版與操作流程，不代表真的帳號或模型可用。
- 本機整合：驗證本機服務與資料讀寫。
- 兩人實測：驗證不同帳號、電腦、權限與同步。

各項交付應分開記錄這些證據，不用建置成功代替產品驗收。現況與已知限制見 [design.md](design.md)。
